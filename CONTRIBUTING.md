# Вычитка OCR

Официальные источники (Минфин, publication.pravo.gov.ru) публикуют приказы об
утверждении ФСБУ сканами без текстового слоя. Текст пунктов получается через
`etl.ocr_text.extract` (Tesseract 5.x, модель `rus` из `tessdata_best`) и затем
обязан быть выверен человеком построчно по оригиналу скана — OCR-текст не
попадает в корпус без вычитки.

При вычитке каждого стандарта, распознанного из приказа 204н, целенаправленно
проверяйте следующие классы ошибок, уже встречавшиеся на практике:

| Класс ошибки | Пример искажения | Как проверять |
|---|---|---|
| Буква подпункта распознаётся как цифра | `б)` → `6)` | Сверять маркеры подпунктов визуально со сканом, не доверять цифрам в начале строки внутри перечней |
| Ноль в дате распознаётся как `@` | `17.09.2020` → `17.09.202@` | Сверять все даты в тексте посимвольно со сканом |
| Вставленные тире на месте выключки (обоснованного выравнивания) | лишний `-` в месте пробела при выравнивании по ширине | Проверять места, где в оригинале текст выключен по ширине страницы |
| Разрывы слов на границе страниц | слово, начатое на одной странице скана и продолженное на следующей, может остаться разорванным или дать лишний перенос после `normalise_hyphenation` | Проверять последнюю и первую строки соседних страниц на стыке |

Эти классы ошибок не исчерпывающие — при обнаружении нового устойчивого искажения
добавьте строку в таблицу.
