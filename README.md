# pbu-fsbu-mcp

MCP-сервер с текстами российских стандартов бухгалтерского учета (ПБУ и ФСБУ).

## Что он делает

- Отдаёт точный текст пункта стандарта с реквизитами приказа Минфина и номером редакции.
- Ищет пункты по естественно-языковому запросу.
- Учитывает даты: ответ всегда дан «на дату», статус стандарта на эту дату указывается явно.

## Чего он не делает

- Не консультирует и не интерпретирует нормы за пределами точного текста стандарта.
- Не обращается в сеть во время работы.
- Пока не проецирует пункты стандартов на объекты 1С:Бухгалтерии и не даёт ссылок на ИТС — это план 3.

## Текущее состояние корпуса

Сейчас в корпусе один стандарт — ФСБУ 6/2020 «Основные средства», одна редакция,
102 пути к пунктам (52 нумерованных пункта и 50 подпунктов). Остальные 28 стандартов
ПБУ и ФСБУ добавляются в плане 2 (ETL).

Доступные инструменты: `list_standards`, `get_standard`, `get_clause`, `search_clauses`.
Ресурс: `pbu-fsbu://registry`.

## Источники

- [Минфин России — Федеральные стандарты бухгалтерского учёта](https://minfin.gov.ru/ru/perfomance/accounting/accounting/standart/positions/)
- [publication.pravo.gov.ru — официальное опубликование правовых актов](http://publication.pravo.gov.ru/Help/Index)

Официальные источники публикуют эти акты как сканы без текстового слоя. Тексты пунктов
получены распознаванием (Tesseract 5.x, модель `rus` из `tessdata_best`) официального
скана и затем выверены вручную построчно по оригиналу.

Нормативные правовые акты не являются объектами авторского права (ст. 1259 ГК РФ).
Код распространяется под MIT, условия на данные — в `data/LICENSE`.

## Установка

### Codex CLI

`~/.codex/config.toml`:

```toml
[mcp_servers.pbu_fsbu]
url = "http://192.168.100.172:18010/mcp"
```

### Claude Code

```bash
claude mcp add --transport http pbu-fsbu http://192.168.100.172:18010/mcp
```

### Claude Desktop

Claude Desktop не может подключиться к адресу в локальной сети: приложение отклоняет
схему `http://`, а соединение custom connector устанавливается из облака Anthropic,
которое не достучится до `192.168.x.x`. Codex CLI и Claude Code — локальные процессы
и обращаются к LAN-адресу напрямую, поэтому им достаточно конфигурации выше.

Для Claude Desktop запускайте сервер локально в stdio-режиме — корпус самодостаточен,
сеть не нужна:

```json
{
  "mcpServers": {
    "pbu-fsbu": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/prokopchuk/pbu-fsbu-mcp", "pbu-fsbu-mcp"]
    }
  }
}
```

## Разработка

```bash
uv sync --all-groups
uv run python -m etl.build_db
uv run python -m etl.validate
uv run pytest
```

Источник истины — YAML в `data/sources/`. Файл `data/build/pbu_fsbu.db` собирается из них
и в репозиторий не коммитится.

### OCR-тесты и Tesseract

`uv run --group etl pytest` включает тесты распознавания (`tests/test_ocr_text.py`),
которым нужен установленный локально Tesseract 5.x с моделью `rus`. Если бинарник
или модель не найдены, эти тесты автоматически пропускаются (`SKIPPED`) — остальной
набор тестов от этого не зависит.

Чтобы OCR-тесты реально выполнялись, установите Tesseract 5.x с языковым пакетом `rus`
и, если он не в стандартном расположении, укажите пути через переменные окружения:

- `TESSERACT_CMD` — путь к исполняемому файлу `tesseract` (нужно, если бинарник не в `PATH`).
- `TESSDATA_PREFIX` — путь к каталогу с моделями (`*.traineddata`), если он нестандартный.

Например, на Windows:

```powershell
$env:TESSERACT_CMD = "C:\Program Files\Tesseract-OCR\tesseract.exe"
$env:TESSDATA_PREFIX = "C:\Users\<user>\.tessdata"
uv run --group etl pytest
```

В CI (Ubuntu) Tesseract и модель `rus` ставятся через `apt-get` — см. `.github/workflows/ci.yml`.
