# pbu-fsbu-mcp

MCP-сервер с текстами российских стандартов бухгалтерского учета (ПБУ и ФСБУ).

## Что он делает

- Отдаёт точный текст пункта стандарта с реквизитами приказа Минфина и номером редакции.
- Ищет пункты по естественно-языковому запросу.
- Учитывает даты: ответ всегда дан «на дату», статус стандарта на эту дату указывается явно.

## Чего он не делает

- Не консультирует и не интерпретирует нормы за пределами точного текста стандарта.
- Не обращается в сеть во время работы.
- Пока не проецирует пункты стандартов на объекты 1С:Бухгалтерии и не даёт ссылок на ИТС — это план 3.

## Текущее состояние корпуса

Корпус охватывает все 29 стандартов бухгалтерского учета из реестра Минфина
(действующие и утратившие силу ПБУ и ФСБУ) — 29 стандартов, по одной редакции
каждый, 1783 пункта с подпунктами.

Доступные инструменты: `list_standards`, `get_standard`, `get_clause`, `search_clauses`.
Ресурс: `pbu-fsbu://registry`.

## Источники

- [Минфин России — Федеральные стандарты бухгалтерского учёта](https://minfin.gov.ru/ru/perfomance/accounting/accounting/standart/positions/)
- [publication.pravo.gov.ru — официальное опубликование правовых актов](http://publication.pravo.gov.ru/Help/Index)

Основной источник текста пункта — собственная страница стандарта на сайте Минфина
(`https://minfin.gov.ru/ru/document?id_4=NNNN`, ссылка есть в реестре стандартов):
там текст отдаётся обычным серверным HTML, без сканов и без OCR, и доступен даже для
стандартов старше архива publication.pravo.gov.ru (тот начинается примерно с ноября
2011 года).

Исключение — ФСБУ 27/2021: его страница на сайте Минфина не содержит текста вообще,
только `<iframe>` с PDF-вьювером. Для этого единственного из 29 стандартов текст
получен распознаванием официального скана приказа с publication.pravo.gov.ru
(Tesseract 5.x, модель `rus` из `tessdata_best`). OCR — документированный резервный
путь на случай, если у будущего стандарта тоже не окажется текста на странице
Минфина, а не основной способ получения текста корпуса.

Во всех случаях текст выверяется построчно по официальному акту вручную перед
переносом файла из `data/drafts/` в `data/sources/standards/`.

### Что не входит в корпус

Приложения к самому стандарту (не к утверждающему приказу) — образцы форм отчётности,
развёрнутые числовые примеры, оформленные как отдельное приложение с собственной
нумерацией — в корпус не входят. Формально они часть акта, но их собственная
нумерация («1.», «2.» …) начинается заново и конфликтует с пунктами самого стандарта,
поэтому `etl.minfin_document._one_copy_of_the_standard` отрезает текст с заголовка
приложения и до конца документа. Отличие от рабочих примеров внутри пунктов (см. ПБУ
18/02 пп. 14–15, где числовой пример — часть текста самого пункта, а не отдельное
приложение) — только в разметке источника: у настоящего приложения есть собственный
заголовок вида «Приложение к Положению по бухгалтерскому учету «…»».

Стандарты, где отрезано приложение (тест `test_html_sourced_standard_reproduces_byte_for_byte`
регенерирует корпус из тех же HTML-снимков и проверяет, что отрезание не съезжает):

| Стандарт | Отрезано |
|---|---|
| ПБУ 8/2010 | 12 010 симв. |
| ПБУ 24/2011 | 4 062 симв. |
| ПБУ 16/02 | 3 814 симв. |
| ПБУ 19/02 | 3 208 симв. |
| ПБУ 7/98 | 2 768 симв. |
| ПБУ 18/02 | 2 372 симв. |
| ПБУ 3/2006 | 1 508 симв. |

Нормативные правовые акты не являются объектами авторского права (ст. 1259 ГК РФ).
Код распространяется под MIT, условия на данные — в `data/LICENSE`.

## Установка

### Codex CLI

`~/.codex/config.toml`:

```toml
[mcp_servers.pbu_fsbu]
url = "http://192.168.100.172:18010/mcp"
```

### Claude Code

```bash
claude mcp add --transport http pbu-fsbu http://192.168.100.172:18010/mcp
```

### Claude Desktop

Claude Desktop не может подключиться к адресу в локальной сети: приложение отклоняет
схему `http://`, а соединение custom connector устанавливается из облака Anthropic,
которое не достучится до `192.168.x.x`. Codex CLI и Claude Code — локальные процессы
и обращаются к LAN-адресу напрямую, поэтому им достаточно конфигурации выше.

Для Claude Desktop запускайте сервер локально в stdio-режиме — корпус самодостаточен,
сеть не нужна:

```json
{
  "mcpServers": {
    "pbu-fsbu": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/prokopchuk/pbu-fsbu-mcp", "pbu-fsbu-mcp"]
    }
  }
}
```

## Обновление корпуса

Корпус собирается из YAML в `data/sources/standards/`. Порядок обновления при выходе
нового приказа Минфина (новый стандарт или поправка к действующему):

1. `uv run --group etl python -m etl.watch --live` — сравнивает реестр стандартов на
   сайте Минфина с корпусом и показывает расхождения (новые/пропавшие стандарты,
   изменившиеся реквизиты приказа, даты применения).
2. `uv run --group etl python -m etl.draft_yaml --live` — вытягивает текст пунктов
   (сперва с HTML-страницы стандарта на сайте Минфина, при её отсутствии — через OCR
   скана с publication.pravo.gov.ru) и кладёт черновик в `data/drafts/`.
3. Вычитать текст пунктов построчно по официальному приказу, перенести файл в
   `data/sources/standards/`, удалить баннер `# ЧЕРНОВИК`.
4. `uv run python -m etl.build_db && uv run python -m etl.validate`.
5. `uv run --group etl pytest`.

Раз в неделю то же сравнение реестра с корпусом выполняет workflow `etl-watch` и при
расхождении открывает pull request с отчётом. Автоматического мёржа нет: новый приказ
читает и вычитывает человек.

## Разработка

```bash
uv sync --all-groups
uv run python -m etl.build_db
uv run python -m etl.validate
uv run pytest
```

Источник истины — YAML в `data/sources/`. Файл `data/build/pbu_fsbu.db` собирается из них
и в репозиторий не коммитится.

### OCR-тесты и Tesseract

`uv run --group etl pytest` включает тесты распознавания (`tests/test_ocr_text.py`),
которым нужен установленный локально Tesseract 5.x с моделью `rus`. Если бинарник
или модель не найдены, эти тесты автоматически пропускаются (`SKIPPED`) — остальной
набор тестов от этого не зависит.

Чтобы OCR-тесты реально выполнялись, установите Tesseract 5.x с языковым пакетом `rus`
и, если он не в стандартном расположении, укажите пути через переменные окружения:

- `TESSERACT_CMD` — путь к исполняемому файлу `tesseract` (нужно, если бинарник не в `PATH`).
- `TESSDATA_PREFIX` — путь к каталогу с моделями (`*.traineddata`), если он нестандартный.

Например, на Windows:

```powershell
$env:TESSERACT_CMD = "C:\Program Files\Tesseract-OCR\tesseract.exe"
$env:TESSDATA_PREFIX = "C:\Users\<user>\.tessdata"
uv run --group etl pytest
```

В CI (Ubuntu) Tesseract и модель `rus` ставятся через `apt-get` — см. `.github/workflows/ci.yml`.
